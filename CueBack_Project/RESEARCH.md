# Research, Differentiation, and Evidence

## 1. Research thesis

The core thesis is that interruption recovery is a distinct problem from task planning: the user may know the task but need to reconstruct the temporary working state around it.

The supplied CueBack analysis specifically frames the system around cognitive state reconstruction, prospective intent, spatial anchoring, and a combination of machine-observable state with human-authored intent. ## 2. Research areas to cite in the pitch

### Task resumption

Useful evidence themes:

- interruptions create resumption lag,
- longer interruptions can increase recovery difficulty,
- contextual cues can help retrieve suspended goals,
- reconstructing task context can improve resumption.

### Human + machine context

The supplied technical analysis highlights that machine telemetry can preserve observable state while human notes can preserve strategic/forward-looking intent. This motivates CueBack's hybrid model: automatic observation + minimal user intent capture. fileciteturn2file0L38-L88

## 3. Claims that require caution

Do **not** state as proven facts unless the exact primary source has been rechecked:

- a universal 2–8 second interruption lag,
- a universal “60%+ reduction,”
- a universal 10–15 minute restart requirement,
- a universal 20-minute optimal reminder point,
- “no competitors exist,”
- “CueBack is the first app to do this.”

The current market includes adjacent products and at least one productivity product that advertises interruption recovery as a feature. Therefore, use the narrower and defensible positioning:

> Current productivity products primarily emphasize planning, distraction prevention, information capture, or broad memory. CueBack makes structured post-interruption context recovery its core workflow.

## 4. Market positioning

### Adjacent category examples

- Screenshot-to-reminder apps convert screenshots/images into reminders or actions.
- General AI memory products preserve broad personal history.
- Task planners store what needs to be done.
- Focus blockers reduce interruptions.
- Some planners advertise interruption recovery.

CueBack should differentiate through the exact workflow:

```text
automatic task-state capture
        +
return detection
        +
adaptive reconstruction
        +
exact next action
        +
re-entry measurement
```

## 5. Product hypothesis

The key hypothesis is:

> Users lose more time rebuilding working context than remembering the title of the task.

A hackathon demo can test this with a simple repeated-task comparison:

```text
Return without CueBack → user narrates what they remember
Return with CueBack    → user follows Warm Start
```

Do not call the result a scientific experiment unless the methodology is appropriate. It is a product demonstration/user test.

## 6. Commercial differentiation

CueBack's moat is not the summary text. The defensible workflow is the combination of:

1. source-aware structured context,
2. automatic session boundaries,
3. context identity/matching,
4. human intent capture only when needed,
5. adaptive reconstruction depth,
6. delta-aware return state,
7. measurable re-entry time.
